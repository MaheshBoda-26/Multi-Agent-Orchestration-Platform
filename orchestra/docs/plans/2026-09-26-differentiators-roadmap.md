## Phase A — Reliability layer (branch `feature/reliability-scores`)

> **Why:** Frontier 2026 signal — agent trust/accountability infrastructure. The supervisor routes and escalates using measured per-specialist reliability, not vibes.
> **Design (locked):** Beta-Binomial scoring with exponential decay. Per (specialist, task_family): posterior mean p̂ = (α + Σ wᵢ·xᵢ) / (α+β + Σ wᵢ), where wᵢ = 2^(−age_days/30) · source_weight. Sources and weights: reviewer verdict = 1, deterministic grader = 1, **human HITL override = 3** (locked 2026-09-26). Prior α=β=1. Half-life 30 days. No LLM inside scoring — deterministic and auditable.
> **Exit:** supervisor routing and second-failure escalation read scores; dashboard shows them; a run with a deliberately crippled specialist demonstrably reroutes.

- [ ] **A1: `migrations/008_agent_outcomes.sql` + `reliability/store.py`** — append-only outcomes table (specialist, family, success, source, weight, created_at); score computation with decay. → Verify: unit test feeds scripted outcomes, asserts decayed p̂ against hand-computed numbers; HITL-override rows score 3×. → `feat: record per-specialist outcomes and compute decayed reliability scores`
- [ ] **A2: Outcome recording hooks** — after specialist completes (reviewer verdict, grader result), after HITL takeover (human override). → Verify: integration test run produces outcome rows with correct sources/weights. → `feat: record outcomes from reviewer, grader and human overrides`
- [ ] **A3: Routing + escalation wiring** — `graph/supervisor.py` prefers specialists above threshold; second-failure escalation becomes score-aware; thresholds in `config/escalation.yaml`, no hard-coded numbers. → Verify: unit test with crippled fake specialist shows reroute; existing 140 tests stay green. → `feat: route and escalate using reliability scores`
- [ ] **A4: API + dashboard** — `GET /stats/reliability`; extend `web/dashboard.html`. → Verify: curl returns per-specialist p̂, trial counts, and weights. → `feat: expose reliability scores on the dashboard`
- [ ] **A5: Cold-start ablation in eval harness** — new config `no-reliability`; measure first-N-tasks behavior with no priors. → Verify: `evals/results.md` gains the row; negative result published if routing doesn't help. → `test: measure reliability routing against the no-reliability config`
